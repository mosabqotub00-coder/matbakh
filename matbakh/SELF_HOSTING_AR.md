# رفع مطبخي على استضافة مستقلة

هذه حزمة مصدر كاملة، لا نسخة بيانات المطعم. يمكن بناء الواجهة والخادم وتشغيلهما على استضافة تدعم **Node.js 22 أو Docker، وقاعدة MySQL 8 أو أحدث متوافقة**. لا تكفي استضافة HTML فقط، ولا رفع `client` أو `dist/public` إلى استضافة PHP تقليدية. الحزمة لا تتضمن كلمات المرور والجلسات والطلبات الحالية أو مفاتيح Push؛ توجد بها ملفات التهيئة والهجرات والبيانات الابتدائية فقط.

## اختيار الطريق

إذا هدفك أن يدخل الموظفون مباشرة إلى دومينك دون ظهور رابط Manus، ربط دومين خاص بالموقع الحالي هو الأقل تعقيدًا؛ تبقى الاستضافة لدى Manus. أما الاستقلال الكامل، فاختر استضافة Node.js مع MySQL أو VPS/Docker. لا تختار استضافة أو تشتريها قبل التأكد من دعم الخادم وقاعدة البيانات والمهام المجدولة وHTTPS. لا يوجد نشر خارجي أو شراء ضمن هذا التسليم.

## الطريقة الأولى: خادم يدعم Docker Compose

انقل مجلد `matbakh` الموجود داخل ZIP إلى الخادم، مثل `/opt/matbakh`. يجب أن يتوفر Docker وCompose وReverse Proxy يدعم HTTPS. أوامر التهيئة التالية **لقاعدة جديدة فقط**، وليست أوامر تطبق على قاعدة المطعم الحالية.

```bash
cd /opt/matbakh
cp .env.example .env
chmod 600 .env
openssl rand -hex 32
```

كرر توليد قيمة عشوائية منفصلة لكل من `MYSQL_PASSWORD` و`MYSQL_ROOT_PASSWORD` و`MAINTENANCE_TOKEN`، ثم اكتبها في `.env`. استعمال كلمات مرور hex يتجنب مشكلة ترميز الرموز داخل DATABASE_URL. لا ترسل الملف إلى Git أو أي رابط عام. ملف Compose يمرر اتصالًا داخليًا إلى خدمة `db` بدل DATABASE_URL المثال.

```bash
mkdir -p private-credentials
chmod 700 private-credentials
docker compose up -d --build
docker compose exec -T app pnpm db:migrate
docker compose exec -T app pnpm db:assign-v2
docker compose exec -T app pnpm bootstrap:manager --output /run/matbakh-private/manager-credentials.json
```

يُنشئ الترتيب أعلاه الجداول والفروع الابتدائية ثم مديرًا عامًا جديدًا بلا فرع. يكتب أمر التهيئة بيانات الدخول في `private-credentials/manager-credentials.json` الخاص، ولا يطبع كلمة المرور في السجل. افتح الملف على خادمك، ادخل أول مرة وغيّر الكلمة المؤقتة. لا تعِد تهيئة المدير على قاعدة فيها حسابات، ولا تشغّل `db:assign-v2` على بيانات مستوردة بدون مراجعة سجل الترحيل.

```bash
curl http://127.0.0.1:3000/api/health
docker compose logs --tail=50 app
```

المنفذ 3000 مربوط بالـloopback فقط، وقاعدة MySQL غير مكشوفة على منفذ عام. اجعل Nginx أو Reverse Proxy الخاص باستضافتك يرسل الدومين إلى `http://127.0.0.1:3000` مع تمرير `Host` و`X-Forwarded-Proto`، وفعل شهادة TLS صحيحة. لا تعرض منفذ قاعدة البيانات للعامة. Volume المسمى `mysql_data` يحفظ البيانات بين إعادة تشغيل الحاويات؛ **إياك استخدام `docker compose down -v` على بيانات تريد الاحتفاظ بها**. وجود Volume ليس نسخة احتياطية.

## الطريقة الثانية: استضافة Node.js مع MySQL مُدارة

فك الحزمة على الاستضافة. اضبط `DATABASE_URL` الحقيقي لقاعدة MySQL، و`DEPLOYMENT_MODE=standalone` و`MAINTENANCE_TOKEN` قوي. بعض الاستضافات توفر PORT تلقائيًا؛ التطبيق يحترمه. لا تحتاج مفاتيح Manus لتسجيل الدخول المحلي وإدارة الطلبات والصوت.

```bash
corepack enable
corepack prepare pnpm@10.18.0 --activate
pnpm install --frozen-lockfile
pnpm build
pnpm db:migrate
pnpm db:assign-v2
mkdir -p /home/YOUR_USER/matbakh-private
chmod 700 /home/YOUR_USER/matbakh-private
pnpm bootstrap:manager --output /home/YOUR_USER/matbakh-private/manager-credentials.json
pnpm start
```

استبدل المسار بـمسار حقيقي **خارج مجلد المشروع** يملكه حسابك، واضبط تشغيلًا دائمًا بواسطة إدارة العمليات أو خدمة استضافتك مع إعادة التشغيل عند الفشل. لا تعتمد على ترك جلسة SSH مفتوحة. شغّل التطبيق عبر HTTPS النهائي؛ الميكروفون والبث وPush والكوكي الآمن تعتمد عليه.

## فحص التأخير المستقل وPush

أضيف `POST /api/maintenance/deadlines` للاستضافة المستقلة فقط. يرفض الطلب بلا `Authorization: Bearer <MAINTENANCE_TOKEN>` قوي، ولا يعمل على إعداد Manus الحالي. لا تضع المفتاح في JavaScript أو رابط المتصفح. أداة `pnpm deadlines:check` تقرأ البيئة وتستدعي الخدمة نفسها عبر loopback، ويمكن ضبط `DEADLINE_CHECK_URL` إلى رابط HTTPS حقيقي إذا كان جدول الاستضافة خارج حاوية التطبيق.

جرب الفحص مرة على الخادم المستقل بعد الهجرات:

```bash
# داخل مشروع Node
pnpm deadlines:check
# أو Docker
docker compose exec -T app node scripts/check-deadlines.mjs
```

ثم أضف في Cron الخادم سطرًا واحدًا كل دقيقة. مثال Docker التالي يحتاج مسار `docker` الصحيح على خادمك:

```cron
* * * * * cd /opt/matbakh && /usr/bin/docker compose exec -T app node scripts/check-deadlines.mjs >> /var/log/matbakh-deadlines.log 2>&1
```

في استضافة Node استعمل مدير الجدولة لديها أو مسار Node الحقيقي. لا تُشغل جدولين لنفس المهمة بلا سبب. راجع نجاح التنفيذ والتغير في سجلات الطلبات، وليس HTTP200 وحده؛ تقرير المراجعة يذكر ملاحظة ينبغي إصلاحها حول دلالة عداد `emitted` عند فشل حفظ الحدث أو تكراره.

عند استخدام `compose.yaml` الموجود في هذه الحزمة، توجد خدمة `deadline-check` تشغّل الفحص تلقائيًا كل دقيقة. في هذه الحالة لا تضف Cron خارجيًا لنفس الفحص، حتى لا تشغّل عاملين متوازيين بلا حاجة.

لتفعيل إشعارات الهاتف، اضبط `VAPID_SUBJECT` إلى دومين HTTPS النهائي أو احفظ الرابط من إعدادات الإدارة المتقدمة، ثم افتح الدومين على كل جهاز وفعل اشتراك Push. **حقل taskUid في الواجهة يخص جدول Manus، وليس Cron المستقل**؛ حالة ربط جدول Manus لا تثبت تشغيل Cron الخارجي. لا تعدل الحقل لتختلق نجاحًا. تغيير الدومين يتطلب موافقات/اشتراكات على العنوان الجديد. قد يشترط iPhone تثبيت تطبيق الويب، ولا يُضمن تجاوز الكتم أو عدم الإزعاج. البث الحي يحتاج صفحة مفتوحة وتفاعلًا لتفعيل الصوت.

## بيانات المطعم الحالية والنسخ الاحتياطي

إذا تريد الانتقال مع كل البيانات، يلزم تصدير MySQL واستيرادها إلى القاعدة الجديدة بعملية خاصة؛ البيانات الصوتية والتسجيلات محفوظة في قاعدة MySQL، فتدخل ضمن نسخها. لا يكفي ZIP المصدر. تحفظ نسخة البيانات كلمات مرور مجزأة ومفاتيح حساسة وسجلات عمل، لذلك لا تنشرها ولا تضمّنها في حزمة عامة. بعد الاستيراد لا تعِد bootstrap أو ترحيل الفروع بلا مراجعة journal؛ خطط أيضًا لإلغاء الجلسات القديمة وتجديد اشتراكات Push على الدومين الجديد.

احتفظ بنسخة دورية مشفرة خارج الخادم، واختبر الاستعادة في قاعدة اختبار قبل الاعتماد. لا تحذف الصوت أو الإشعارات أو الطلبات تلقائيًا قبل تحديد مدة الاحتفاظ. إذا بقيت على Manus، فإن ربط دومين لا ينفذ نقل البيانات المذكور.

لإنشاء نسخة احتياطية مضغوطة يدويًا على خادم Node مثبت عليه `mysqldump`:

```bash
BACKUP_DIR=/var/backups/matbakh pnpm db:backup
```

يُنشأ الملف بصلاحيات خاصة داخل مجلد النسخ. انقل النسخة إلى مكان مستقل ومشفّر، ولا تحفظها داخل مجلد المشروع العام.

## الوردية المعتادة للموظف

عند إضافة أو تعديل موظف يوجد حقل **الوردية المعتادة (اختياري)**: صباحي، مسائي، مرن، أو بدون تحديد. هذه المعلومة تنظيمية فقط، ولا تمنع الموظف من العمل في وردية مختلفة ولا تغيّر صلاحياته أو وصوله أو توزيع الطلبات. ترحيل قاعدة البيانات `0005_optional_staff_shift` يضيف الحقل بشكل آمن وقابلًا للبقاء فارغًا للحسابات القديمة.

## إزالة العلامة والدومين

في استضافة المصدر المستقلة، لا يحقن خادم Manus شارته في صفحاتك؛ لا تحتاج إخفاءها بحيلة CSS. هذا لا يلغي الحاجة لتجهيز HTTPS وقاعدة البيانات والجدولة. أما الموقع الذي يبقى مستضافًا على Manus، فإزالة الشارة من Settings → Advanced → Hide Manus badge، وربط الدومين من إعدادات الدومين وبسجلات DNS الفعلية التي توفرها المنصة. الإتاحة تخضع لخطة الحساب؛ التفاصيل والمصادر في تقرير المراجعة.

## ما اختُبر وما لم يُنفذ

نجح بناء مصدر Node وفحص TypeScript واختبارات الوحدة. تتضمن اختبارات المسار المستقل رفض مفتاح غائب/خاطئ ورفض وضع Manus. الاختبارات لا تنشئ بيانات في قاعدة المطعم. لا تتوفر أداة Docker في هذه البيئة، لذلك **لم يُختبر بناء الحاويات أو قاعدة جديدة فعلية**؛ تعليمات Compose إعداد قابل للمراجعة والتنفيذ على خادمك وليست إثبات نشر. لا يوجد شراء استضافة أو دومين أو نقل قاعدة أو تشغيل Cron خارجي في هذه الجلسة. راجع `SYSTEM_REVIEW_2026-10-28.md` لإصلاحات الأمان والموثوقية المقترحة قبل الاعتماد الكامل.

## تسجيل الدخول المستقل (بدون Manus)

- الدخول يعمل بالكامل من قاعدة MySQL في `DATABASE_URL`، بدون أي خدمة خارجية.
- الموظفون الحاليون يدخلون باسم المستخدم كما هو. يمكن لأي موظف ربط بريد إلكتروني اختياري من صفحة الإشعارات ← إعدادات الهاتف، ثم الدخول به.
- لا يوجد تسجيل ذاتي. الحسابات الجديدة ينشئها مدير النظام أو المطوّر أو مدير الفرع (لفرعه فقط) من لوحة الإدارة، مع الدور والفرع، كما في السابق.
- كلمات المرور تُخزَّن بتجزئة scrypt مع salt عشوائي لكل حساب، ولا تُحفظ كنص.
- الجلسة: كوكي HttpOnly وSecure، و`SameSite=Lax` افتراضيًا. تُخزَّن بصمة SHA-256 للرمز فقط في جدول `staff_sessions`. الخروج أو تغيير كلمة المرور يُلغي الجلسات.

### المتغيرات

| المتغير | مطلوب | الوصف |
|---|---|---|
| `DATABASE_URL` | نعم | `mysql://user:password@host:3306/matbakh` |
| `MAINTENANCE_TOKEN` | نعم | رمز عشوائي طويل لفحص المهلات |
| `DEPLOYMENT_MODE` | نعم | `standalone` |
| `NODE_ENV` / `PORT` | نعم | `production` / `3000` |
| `COOKIE_SAME_SITE` | لا | `lax` (افتراضي) أو `strict` أو `none` (فقط إذا فُتح الموقع داخل iframe) |
| `COOKIE_SECURE` | لا | `true` افتراضيًا. اجعله `false` فقط للتجربة على `http://localhost` |
| `VAPID_SUBJECT` | لا | رابط الموقع لإشعارات المتصفح |
| `EXPO_ACCESS_TOKEN` | لا | فقط إذا فعّلت الحماية المعززة لإشعارات Expo |

الموقع يجب أن يعمل خلف HTTPS (مثل Nginx أو Caddy). الخادم يثق برؤوس `X-Forwarded-*` القادمة من الشبكة المحلية فقط.

### أول مدير (Admin)

يوجد في البيانات المنقولة حسابا `manager` و`admin` بدور مدير النظام، ومنهما تُنشأ بقية الحسابات. لترقية حساب موجود إلى مدير نظام (على الخادم نفسه فقط، لا يمكن ذلك من المتصفح):

```bash
docker compose exec app node scripts/promote-admin.mjs owner@example.com
# أو بدون Docker
pnpm admin:promote owner@example.com
```

إذا كانت القاعدة فارغة تمامًا استخدم `pnpm bootstrap:manager --output /مسار/خارج/المشروع/credentials.json`.

### الترقية من نسخة سابقة

```bash
docker compose run --rm app pnpm db:migrate   # يضيف أعمدة جديدة فقط، بدون حذف بيانات
docker compose up -d --build
```
