# تقرير التدقيق الشامل لمشروع مطبخي

**التاريخ:** 2026-10-28  
**النطاق:** مراجعة المصدر، واجهة الطلبات والمطبخ والمدير، الصلاحيات، الإشعارات، البث، التكامل، الاختبارات، البناء، وخيارات الاستضافة.

## الملخص التنفيذي

المشروع متقدم ومناسب كأساس تشغيلي حقيقي: توجد دورة طلب واضحة، أدوار وصلاحيات، عزل للفروع، أرشيف، تمديد للمهل، إشعارات، بث صوتي، تكامل وارد، Docker، وتعليمات استضافة مستقلة. لكنه لا يُعتبر مثبت الجاهزية الإنتاجية الكاملة قبل معالجة بعض نقاط الموثوقية واختبار الأجهزة والشبكات والجدولة في بيئة حقيقية.

تم تنفيذ تعديل مباشر على وضوح الوقت والتاريخ: تم تكبير أوقات وتواريخ الطلبات المكتملة، السجل التاريخي، أوقات الجاهزية والاستلام، ومعلومات التوقيت في بطاقات الطلب، مع قواعد خاصة للشاشات الصغيرة حتى لا ينكسر التخطيط.

## نتائج التحقق

- فحص TypeScript: ناجح.
- الاختبارات: **17 ملفًا، 96 اختبارًا ناجحًا، 0 فشل**.
- بناء الواجهة والخادم: ناجح.
- تحذير البناء غير المانع: ملف JavaScript النهائي كبير نسبيًا، ويستحسن لاحقًا تقسيمه عبر `dynamic import`.
- تحذير البناء غير المانع: وسم إعداد `/api/platform/config.js` يحتاج `type="module"` إن كان ذلك متوافقًا مع آلية المنصة.
- لم تُنفذ هجرات قاعدة بيانات أو عمليات كتابة على بيانات مطعم فعلية.
- لم يُثبت تشغيل Push على هاتف مقفل أو تشغيل Cron/Heartbeat في بيئة نشر فعلية.

## ما هو مكتمل وقوي

1. دورة الطلب الأساسية موجودة: `new → preparing → ready → received` مع سجل للمراحل والتوقيتات.
2. توجد أدوار متعددة وصلاحيات وعزل للفروع، مع تجزئة كلمات المرور وإدارة جلسات.
3. الواجهات الأساسية موجودة: إرسال الطلب، شاشة المطبخ، لوحة المدير، الأرشيف، المنتجات، الموظفون، الفروع، الإشعارات، والبث.
4. يوجد أرشيف يحفظ أوقات الإرسال والقبول والجاهزية والاستلام، والملاحظات والتسجيلات الصوتية.
5. الإشعارات الداخلية وPush وService Worker موجودة مع مفاتيح منع التكرار.
6. البث الصوتي أحادي الاتجاه مقيد بالقسم والفرع وله حد زمني وتسجيل وأرشفة.
7. الاستضافة المستقلة مدعومة عبر Node.js 22 أو Docker مع MySQL 8+، وملف Compose وتعليمات Cron ونسخ احتياطي.
8. يوجد API وارد محمي بمفتاح مرتبط بالفرع، وOutbox للتكامل.

## أمور يجب إصلاحها قبل الاعتماد الكامل

### أولوية P0

- **منع تكرار العمليات:** إنشاء الطلب وتمديده وبعض الانتقالات لا تملك idempotency key موحدًا؛ النقر المكرر أو إعادة محاولة الشبكة قد تنشئ طلبًا مكررًا أو تضيف التمديد مرتين.
- **تسجيل الخروج عند تعطل قاعدة البيانات:** يوجد مسار قد يمسح الكوكي ويعيد نجاحًا رغم عدم ضمان إبطال الجلسة من قاعدة البيانات.
- **تشغيل فحص المهل فعليًا:** وجود وظيفة فحص التأخير لا يكفي؛ يجب نشر Heartbeat أو Cron، وإظهار آخر تشغيل ونتيجة الفشل، ومنع تشغيل عاملين متوازيين.
- **حالات أخطاء الواجهة:** بعض الشاشات قد تظهر قائمة فارغة أو عبارة «متصل» عند فشل الاستعلام. يجب الفصل بين `loading / error / stale / empty` مع زر إعادة المحاولة وآخر تحديث.
- **دقة عداد الإشعارات:** يجب التفريق بين الإشعار المحفوظ، المكرر، الفشل في الحفظ، والفشل في Push بدل اعتبارها كلها مرسلة.

### أولوية P1

- تنفيذ عامل Outbox حقيقي مع lease، محاولات وإعادة إرسال، backoff، timeout، وحالة تسليم.
- عدم تفعيل UNIFYERP قبل توثيق عقد المزود، التوقيع، ACK، حالات الفشل، وبيئة اختبار.
- إضافة فحوص سلامة مرجعية للفروع والطلبات والمستخدمين، أو قيود FK بعد تنظيف البيانات القديمة.
- جعل انتهاء البث مستقلًا عن فتح صفحات العملاء، وإكمال handshake إنشاء سجل البث قبل التقاط الصوت.
- فصل `liveness` عن `readiness` وإضافة فحص قاعدة البيانات والجدولة والتخزين، لأن `/api/health` الحالي لا يثبت جاهزية كل الخدمات.
- وضع سياسة نسخ احتياطي مشفّر خارج الخادم واختبار استعادة دوري؛ Volume Docker ليس Backup.

### أولوية P2

- إضافة كيان ورديات وتعيين الموظفين إذا كانت تقارير الأداء مطلوبة.
- إضافة pagination وسياسة احتفاظ للإشعارات والتسجيلات وOutbox.
- إضافة «آخر مزامنة» واضحة بدل الإيحاء بأن الاتصال حي دائمًا.
- تحسين تقسيم حزمة JavaScript الكبيرة عبر lazy loading.
- تأجيل WebSocket وضغط الصوت والتحليلات المتقدمة حتى تثبت الحاجة بقياسات فعلية.

## مقارنة الاستضافة

### Manus

مناسبة كبداية وأقل عبئًا تشغيليًا: لا تحتاج إلى إدارة VPS وقاعدة البيانات والجدولة بنفسك، ويمكن ربط دومين خاص دون نقل البيانات. لكنها تعتمد على خدمات المنصة في أجزاء مثل OAuth وHeartbeat وبعض التخزين، ويجب إثبات تشغيل الجدولة وPush في النشر الحقيقي. ربط الدومين لا يعني نقل البيانات تلقائيًا.

### استضافة خارجية

مناسبة إذا كان المطلوب استقلال كامل وتحكم بالبنية التحتية. الحزمة قابلة للتشغيل على Node.js 22 مع MySQL 8+ أو Docker، لكنك ستدير HTTPS وReverse Proxy، migrations، Cron، النسخ الاحتياطي، الاستعادة، المراقبة، التحديثات، وحماية الخادم. ملف ZIP لا يحتوي بيانات الطلبات أو الجلسات أو مفاتيح Push؛ نقل البيانات يحتاج تصدير MySQL وخطة آمنة للتسجيلات والجلسات والاشتراكات.

### التوصية

إذا كان الهدف دخول الموظفين من دومينك فقط، فابقاء التطبيق على Manus مع ربط الدومين هو المسار الأقل مخاطرة. إذا كان الهدف الاستقلال أو التحكم الكامل، فالاستضافة الخارجية ممكنة، لكن لا تبدأ التشغيل الفعلي قبل تجهيز backup/restore وCron وreadiness وHTTPS واختبار الأجهزة.

## التعديل المنفذ

الملف المعدّل هو `client/src/time-readability.css`، وتم فيه:

- تكبير أوقات وتواريخ السجل والطلبات إلى أحجام أوضح.
- تكبير وقت إتمام الطلب والجاهزية والاستلام بصورة بارزة.
- تحسين التفاف النص العربي داخل بطاقات التاريخ.
- إضافة قواعد مناسبة للهاتف دون تغيير القيم الزمنية أو منطق الطلبات.

## القرار النهائي

**المشروع صالح للتطوير والتجهيز، وليس للاعتماد التشغيلي الكامل قبل إصلاح عناصر P0 واختبار النشر والأجهزة.** التعديل البصري المطلوب تم تنفيذه وفحصه عبر TypeScript والاختبارات والبناء.

## إضافات هذه النسخة

- أضيفت الوردية المعتادة الاختيارية للموظف: صباحي، مسائي، مرن، أو بدون تحديد. لا تغيّر الصلاحيات ولا تمنع العمل في وردية مختلفة.
- أضيف ترحيل قاعدة البيانات `0005_optional_staff_shift` لإضافة الحقل للحسابات الحالية دون إلزامها بقيمة.
- أضيفت خدمة `deadline-check` إلى Docker Compose لفحص المهل تلقائيًا كل دقيقة.
- أضيف الأمر `pnpm db:backup` لإنشاء نسخة MySQL مضغوطة، مع توثيق حفظها خارج الخادم.
