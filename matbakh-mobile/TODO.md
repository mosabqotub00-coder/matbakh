# نتائج مشروع مطبخي للجوال

- [x] **تثبيت المعمارية التي تعيد استخدام الموقع والحسابات الحالية.** التطبيق يعرض `https://www.matbakh.click` عبر غلاف Native آمن، ولا ينشئ قاعدة مستخدمين بديلة أو يعيد بناء شاشة السخان أو المطبخ أو الطلبات أو الحالات أو الإدارة أو مركز المطوّر. تبقى الجلسة والفرع والدور والصلاحيات في خادم الموقع نفسه.

- [x] **تنفيذ غلاف Android عربي آمن للموقع الحالي.** يقتصر WebView على نطاق مطبخي، يعرض حالات تحميل وانقطاع شبكة واضحة وزر إعادة محاولة مناسبًا لليد الواحدة، ويحافظ على RTL. لا يستخدم عرضًا تجريبيًا أو HTML ثابتًا، ولا يظهر cashier أو كاشير أو كاونتر. معاينة الويب تعرض الموقع الحي فقط ولا تحاكي Android.

- [x] **تنفيذ جسر الجلسة والجهاز من دون ثقة بهوية محلية.** يعتمد الجسر رسالة الموقع `MATBAKH_AUTH_CHANGED` من `matbakh-web` فقط، ولا يسجل الجهاز عند تغيير كلمة المرور الإجباري. ينشئ Expo token ومعرّف تثبيت بعد جلسة موقع صالحة ويجعل صفحة الموقع تستدعي `nativePush.status/register/unregister/test/acknowledge` بـ cookie الجلسة؛ لا يضع الهاتف المستخدم أو الفرع أو الدور أو session token في الحمولة. فرض إلغاء الحساب/انتهاء الجلسة والفرع غير المصرح به يبقى في الخادم الذي يضيفه مالك الموقع.

- [x] **تنفيذ طبقة إشعارات Android وتوجيه النقر.** ينشئ التطبيق قناة `matbakh-orders-v1` بصوت النظام والأهمية العالية قبل token، ويربط صوت المقدمة بـ Native بعد أن يوقف الموقع beep فقط عند التسجيل الناجح. يتحقق من مسارات `/` و`/kitchen` و`/manager` و`/notifications` فقط ويحافظ على query التذكرة، ويرسل acknowledge للاستلام/الفتح. لا يدّعي تجاوز إذن الإشعارات أو عدم الإزعاج أو force-stop. يبقى الإثبات الحقيقي للهاتف مفتوحًا حتى بناء APK.

- [x] **دعم الصوت والميكروفون بشكل مقيد.** تبقى تسجيلات الصوت وتشغيله داخل الموقع؛ في Android يطلب WebView إذن الميكروفون فقط عندما تبدأ صفحة التسجيل طلب الالتقاط، ولا يطلبه عند التشغيل أو تسجيل الدخول.

- [x] **إعداد رقعة خادم منفصلة وآمنة لموقع مطبخي.** يوثّق العقد `nativePush` والجسر المطلوب في الموقع، من دون نشره أو تعديل قاعدة الموقع أو بيانات الفروع أو كلمات المرور من مشروع الهاتف. مالك الموقع ينفذ النشر المنفصل للخادم الحقيقي.

- [ ] **إعداد بناء داخلي فعلي.** ملف `preview` لـ EAS APK وتكوين Android والقناة والأصول جاهزة. يلزم ربط Expo Dashboard، `EXPO_PUBLIC_EAS_PROJECT_ID`، ملف Firebase المحمي، واعتماد FCM V1 في EAS ثم بناء APK فعلي. لا توجد مفاتيح في المصدر أو المحادثة، ولا ينفذ Sandbox بناء Android release ولا ينشر Google Play.

- [x] **تشغيل الفحوص البرمجية وفحص الموقع والـ API.** مرّ `pnpm check` و`pnpm lint` و47 اختبارًا وظيفيًا، إضافة إلى فحص الموقع الحي و`/api/health` وAPI القالب المحلي. لا تعتبر هذه الفحوص بديلًا عن اختبار الهاتف.

- [ ] **إثبات التسليم على هاتف Android فعلي.** بعد بناء Dashboard/EAS الناجح وتوفر APK، يتم تثبيته على هاتف متصل ثم اختبار: فتح التطبيق وتسجيل الدخول بالحساب الحالي، صلاحيات فرع مختلف، الإشعار في المقدمة، الخلفية، والشاشة المقفلة مع صوت، الضغط لفتح القسم/التذكرة، تسجيل الخروج وإلغاء الربط. لا توضع علامة الإنجاز قبل تسجيل نتيجة تلك التجربة وملف APK الناتج.
